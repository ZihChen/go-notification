## 問題一：go-test job 失敗（exit code 1）

### 現象
`go-test` job 回報 exit code 1，但所有測試實際上都有通過。

### 根本原因（第一層）
Cache 路徑使用絕對路徑（`/go/pkg/mod`、`/root/.cache/go-build`），這些路徑在 project directory 之外，GitLab Runner 無法快取，導致 runner 警告並影響 job 結果。

### 根本原因（第二層，真正原因）
修完 cache 路徑後，新的 CI log 才顯示真正錯誤：  
上傳 `coverage.xml`（36,781 行）到 GitLab 作為 Cobertura report artifact 時，GitLab 回傳 **500 Internal Server Error**，檔案太大超出限制。

### 解法
1. 將所有 cache 路徑改為 project 相對路徑，並設定 `GOPATH`、`GOCACHE`、`GOBIN` 環境變數指向 `.cache/` 目錄
2. 移除 `gocover-cobertura` 的安裝與執行，移除 `artifacts.reports.coverage_report` 區塊
3. 保留 `coverage:` regex，GitLab 仍可從 stdout 擷取覆蓋率百分比

### 相關 commits
- `4937089` fix(ci): move cache paths inside project directory
- `856ce18` fix(ci): remove cobertura artifact upload causing 500 error

### 狀態
✅ **已解決**

## 問題二：build job 失敗（401 Unauthorized on ECR）

### 現象
`build-commit-sha`、`build-dev`、`build-latest` 全部失敗，log 顯示：
```
unauthorized: authentication required
```

### 根本原因
原本的 build template 使用 `docker:latest` + `docker:dind`（Docker-in-Docker）的方式推送 ECR image，但 `macmini-designer` runner 的 Docker executor **不支援 privileged mode**，DinD 無法啟動。

### 解法嘗試過程

#### 嘗試一：docker:dind + aws-cli（失敗）
參考 fat-identity-cat 的做法，使用 `docker:latest` + `services: docker:dind`。  
**結果：** `FATAL: No HOST or PORT found` — macmini-designer runner 不支援 privileged mode，DinD 無法運行。  
Commit: `5dbd32e`

#### 嘗試二：kaniko + 下載 aws-cli v2 binary（失敗，/tmp 不存在）
改用 `gcr.io/kaniko-project/executor:debug`（不需要 privileged mode），在 `before_script` 用 wget 下載 aws-cli v2 ARM64 binary。  
**結果：** `wget: can't open '/tmp/awscliv2.zip': No such file or directory` — kaniko:debug 容器沒有 `/tmp` 目錄。  
Commit: `45421af`

#### 嘗試三：加上 mkdir /tmp + --no-check-certificate（失敗，glibc 缺失）
修正 `/tmp` 不存在問題，加上 `mkdir -p /tmp` 並使用 `wget --no-check-certificate`。  
**結果：** `/tmp/aws/dist/aws: not found` — aws-cli v2 是 glibc binary，kaniko:debug 是 distroless 容器（無 glibc），執行不起來。  
Commit: `bb6afa4`

#### 嘗試四：分離 ecr-auth job（目前方案）
將 AWS 認證流程拆出，新增獨立的 `ecr-auth` job（Alpine image），透過 GitLab `dotenv` artifact 將 ECR token 傳給 kaniko job。

**架構：**
```
ecr-auth (alpine:latest)
  ├─ apk add aws-cli
  ├─ aws sts assume-role → FatcatInternalRunnerAssumeRole
  ├─ aws ecr get-login-password → base64 encode
  └─ ECR_AUTH=<token> → ecr-auth.env (dotenv artifact)
        ↓ needs
build-* (kaniko:debug)
  ├─ 接收 ECR_AUTH 環境變數（來自 dotenv artifact）
  ├─ printf '{"auths":{...}}' > /kaniko/.docker/config.json
  └─ /kaniko/executor build & push
```

Commit: `3564400`

### 目前狀態
⏳ **等待 DevOps 設定 AWS 憑證**

`ecr-auth` job 執行時出現：
```
Unable to locate credentials. You can configure credentials by running "aws login".
```

原因：Alpine 容器內沒有基礎 AWS 憑證（`AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`）可以執行 `sts:AssumeRole`。
