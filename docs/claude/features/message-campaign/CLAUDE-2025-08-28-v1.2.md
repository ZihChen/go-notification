# 會員訊息排程發送系統 v1.2

## 完成狀態
🚧 **開發中** - 會員訊息自動派發設定功能

## 功能概述
- 會員訊息自動派發設定：提供兩個API
  - GET：一個可以透過merchant_id取得指定會員訊息自動派發設定
  - POST/PUT：新增或更新特定merchant_id的會員訊息自動派發設定

## 技術實作
- 資料方面一次新增/更新六筆message-campaign的資料：
  - 四筆是category=1、item=1、2、3 (參考internal/domain/consts/consts.go)
  - 兩筆是category=2、item=4
  - 需要加一個欄位來辨識是否觸發行為
    - Category=1、Item=2是會員+實名驗證，實名驗證成功跟失敗都要設定所以要區分開
    - Category=2、Item=4也是要辨別優惠派發成功跟失敗
  - auto_send的欄位都是true
  - status為 2 (參考internal/domain/consts/consts.go)
  - 新增的時候send_start_time、created_at、updated_at都帶入創建資料的時間、更新的操作只有updated_at會更新成當前時間
  - created_by帶入auto_system

## 資料庫結構設計

### MessageCampaign 表新增欄位
在現有 MessageCampaign 表基礎上新增以下欄位：

```sql
ALTER TABLE message_campaigns 
ADD COLUMN trigger_type VARCHAR(20) DEFAULT 'success' COMMENT '觸發類型: success, failure';

ALTER TABLE message_campaigns 
ADD INDEX idx_merchant_category_item_trigger (merchant_id, category, item, trigger_type);
ALTER TABLE message_campaigns 
ADD INDEX idx_auto_send_status (auto_send, status);
```

### 自動派發設定數據結構
每個merchant會自動建立6筆 MessageCampaign 記錄：

| Category | Item | Trigger Type | Title | Content |
|----------|------|--------------|-------|---------|
| 1 (會員) | 1 (註冊) | success | 會員註冊成功通知 | 歡迎加入我們！您的帳戶已成功建立。 |
| 1 (會員) | 2 (實名驗證) | success | 實名驗證成功通知 | 恭喜您完成實名驗證！ |
| 1 (會員) | 2 (實名驗證) | failure | 實名驗證失敗通知 | 實名驗證失敗，請重新提交資料。 |
| 1 (會員) | 3 (銀行卡) | success | 銀行卡綁定成功通知 | 銀行卡已成功綁定到您的帳戶。 |
| 2 (優惠) | 4 (任務) | success | 優惠派發成功通知 | 恭喜獲得新優惠！請查看您的帳戶。 |
| 2 (優惠) | 4 (任務) | failure | 優惠派發失敗通知 | 優惠派發失敗，請聯繫客服。 |

### 資料約束規則

1. **唯一性約束**: 每個 merchant_id + category + item + trigger_type 組合只能有一筆自動訊息設定
2. **預設值設定**: 
   - `auto_send = true`
   - `status = 2` (已排程)
   - `target = 11` (所有玩家)
   - `created_by = 'auto_system'`
   - `send_start_time = 當前時間`
3. **時間戳管理**:
   - 新增: `created_at`, `updated_at`, `send_start_time` 設為當前時間
   - 更新: 只更新 `updated_at` 為當前時間

```go
    autoSettings.POST("/:merchant_id", h.CreateOrUpdateMerchantAutoSettings) 
    autoSettings.PUT("/:merchant_id", h.CreateOrUpdateMerchantAutoSettings)
}
```

### 2. DTO 結構定義
**檔案位置**: `internal/domain/dto/request.go`

新增 DTO 結構：
```go
type AutoSettingItem struct {
    Category    uint8  `json:"category"    binding:"required,min=1,max=3"`
    Item        uint8  `json:"item"        binding:"required,min=1,max=6"`
    TriggerType string `json:"trigger_type" binding:"required,oneof=success failure"`
    Title       string `json:"title"       binding:"required,max=255"`
    Content     string `json:"content"     binding:"required"`
}

type MerchantAutoSettingsRequest struct {
    Settings []AutoSettingItem `json:"settings" binding:"required,min=1,max=10"`
}

type MerchantAutoSettingsResponse struct {
    MerchantID string             `json:"merchant_id"`
    Settings   []*MessageCampaign `json:"settings"`
}
```
