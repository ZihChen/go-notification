# 會員訊息發送系統新增App推播功能 v1.8

## 完成狀態
✅ **已完成實作** (2025-09-22)

## 功能概述
新增選項讓使用者決定要發送站內信、App推播或兩者都發送，提供更靈活的通知方式。

## 🔧 技術實作詳情

### 1. 資料庫結構變更

#### message_campaigns 表新增欄位
```sql
-- App推播內容欄位
ALTER TABLE message_campaigns ADD COLUMN app_content varchar(255) NULL COMMENT 'App推播通知的內容';

-- 推送類型位元遮罩欄位  
ALTER TABLE message_campaigns ADD COLUMN notification_types tinyint(3) unsigned NOT NULL DEFAULT 1 COMMENT '推送類型位元遮罩: 1=站內信, 2=App推播, 4=其他';
```

#### 新增 merchant_push_api_keys 表
```sql
CREATE TABLE merchant_push_api_keys (
  id bigint(20) unsigned NOT NULL AUTO_INCREMENT,
  global_merchant_id varchar(100) NOT NULL,
  merchant_id bigint(20) unsigned NOT NULL,
  key varchar(100) NOT NULL,
  created_at datetime DEFAULT CURRENT_TIMESTAMP,
  updated_at datetime DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  deleted_at datetime NULL,
  PRIMARY KEY (id),
  INDEX idx_global_merchant_id (global_merchant_id),
  INDEX idx_merchant_id (merchant_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### 2. 位元遮罩設計
- **1**: 站內信
- **2**: App推播  
- **3**: 站內信 + App推播 (1 | 2)
- **4**: 其他推送方式 (預留擴充)
- **可組合**: 支援多種推送方式同時啟用

## 🚀 使用指南

### 1. 商戶設定 API Key
商戶需要先在系統中設定 App 推播的 API key，才能使用 App 推播功能。

### 2. 創建推播活動
在創建訊息活動時，可以：
- 設定 `app_content` 欄位作為 App 推播內容
- 設定 `notification_types` 決定推送方式
- 系統會根據位元遮罩自動判斷發送渠道

### 3. 推播執行流程
1. 系統檢查 `notification_types` 位元遮罩
2. 如果包含 App 推播 (bit 2)，查詢商戶 API key
3. 調用第三方推播服務
4. 記錄推播結果和統計數據
