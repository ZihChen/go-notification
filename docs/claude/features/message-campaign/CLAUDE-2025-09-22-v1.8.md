# 會員訊息發送系統新增App推播功能 v1.8

## 完成狀態

## 功能概述
要新增一個選項可以讓使用者決定要發送站內信還是App推播還是兩個都發

## 技術實作
- message_campaign新增app_content欄位：
  - 型別：varchar(255) 作為App推播通知的內容
- 新增notification_types：
  - 使用位元遮罩 (Bitmask)的方式決定應該是推送到哪個服務並確保擴充性
    - 1: 站內信
    - 2: App推播
    - 4: (其他推送方式) 依此類推
- 新增一個DB Table紀錄每個Merchant的App推播的API key：
  - global_merchant_id varchar(100)
  - merchant_id bigint
  - key varchar(100)
- 會員訊息活動推送到第三方服務：
  - 如果notification_types = 2 or 3，透過message_campaign.merchant_id 取得 App推播的API key
  - 推播的curl如以下：
    ```
      curl --location 'https://cmcat.jvdev.cc/v1/merchant/push_notifications' \
      --header 'x-api-key: MAK:bb647568cdfe2e2356f4f54ab94258f254053606' \
      --header 'Content-Type: application/json' \
      --data '{
      "accounts": [
      "alanbonus0627",
      "winston883"
      ],
      "msg_title": "Test嗨嗨111",
      "msg_body": "Test Body"
      }'
    ```
    - x-api-key帶入API key
    - accounts可帶入多個player的accounts
    - msg_title 帶入 message_campaign.title
    - msg_body 帶入 message_campaign.app_content
- 不要幫我執行./migrate.sh apply指令，這樣會直接把資料表變更遷移到真實數據庫
