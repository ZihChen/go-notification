# 實作DB資料搬遷 v1.6

## 完成狀態

## 功能概述
要把過去三個月內的DB會員訊息資料搬遷到微服務的DB

## 技術實作
1. 使用go指令集的方式執行Migrate操作
2. 資料新增採用UpdateOrCreate方式：
3. 有主鍵約束、重複執行指令不會重複創建資料，而會更新特定欄位
4. 如果有資料漏掉，補上欄位後重複執行指令可以把資料同步回去
5. 考慮有百萬量級以上的資料量，確保在同步資料上的效能
6. fatcat_staging.notifications 搬遷到 ms_fatnotificationcat.message_campaign
   - Migrate邏輯:
     - 透過created_at搜出前三個月的資料
     - category mapping 到 category
       - mapping表：
         - 1 -> member
         - 2 -> bonus
         - 3 -> others
       - item mapping 到 item
         - mapping表：
           - 1 -> registration
           - 2 -> identity_verification
           - 3 -> bank_card
           - 4 -> others
           - 5 -> event
           - 6 -> all
           - 7 -> mission
       - trigger_type 統一寫入 success
       - merchant_id
         - 到fatcat_staging.companies 找 id = 2的資料
         - 透過到fatcat_staging.companies 的 name 來搜尋 ms_fatnotificationcat.merchants 的 name
         - 將merchants.id 寫入 merchant_id
       - global_id
         - 使用uuid.NewString()產生uuid
       - title 同 title
       - content 同 content
       - status
         - deleted_at != nil 為 cancelled
         - deleted_at = nil 為 sent
       - target
         - focus mapping 到 target
           - mapping表：
             - 1 -> high_activity
             - 2 -> low_activity
             - 3 -> not_activity
             - 8 -> player
             - 9 -> level
             - 10 -> tag
             - 11 -> all
       - auto_send 同 auto_send
       - created_at mapping到 send_start_time、send_end_time、created_at
       - updated_at 同 updated_at
       - created_by 同 created_by
       - updated_by 同 updated_by
       - deleted_at 同 deleted_at
7. fatcat_staging.user_notifications 搬遷到 ms_fatnotificationcat.player_message
   - Migrate邏輯:
      - fatcat_staging.notifications.id 與 fatcat_staging.user_notifications.notification_id 關聯
      - ms_fatnotificationcat.message_campaign.id 與 ms_fatnotificationcat.player_message.campaign_id 關聯
      - 同步 message_campaign 的時候一並把關聯的 player_message 同步進 DB
        - global_player_id
          - fatcat_staging.companies 的 name + "PLAYER" + fatcat_staging.user_notifications.user_id組合成的字串
          - ex. 組起來像 FATCAT-PLAYER-16700386 中間用-區隔開來
          - 使用global_player_id 到 ms_fatnotificationcat.players 搜尋如果不存在就不用同步該筆資料到 player_message
      - player_id
        - 為 ms_fatnotificationcat.players 的 id
      - campaign_id
        - 為 ms_fatnotificationcat.message_campaign 的 id
      - is_read 同為 id_read
      - created_at 同 created_at
      - updated_at 同 updated_at
