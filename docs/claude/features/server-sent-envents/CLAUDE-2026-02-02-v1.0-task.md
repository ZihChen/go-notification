## 📋 實作總覽

### 功能範圍

透過 Server-Sent Events (SSE) 協議實現實時推播通知系統,支援:

- ✅ **後端推播 API** (REST + API Key 認證)
  - 廣播推送 (所有線上玩家)
  - 個別推送 (特定玩家清單)
  - 統計資訊查詢

- ✅ **前端接收 API** (SSE + JWT 認證)
  - SSE 長連接接收實時訊息
  - 查詢歷史訊息
  - 標記已讀
  - 刪除訊息

**訊息流向**:

1. **廣播推送**: 後端 API → SSE Service → Redis Pub/Sub (sse:broadcast) → 所有 SSE Pods → 前端客戶端
2. **個別推送**: 後端 API → SSE Service → 查詢路由表 → Redis Pub/Sub (sse:pod:X) → 目標 Pod → 前端客戶端
3. **離線訊息**: SSE Service → Redis Streams → 玩家上線時推送 → 前端客戶端

### ⚠️ 重要說明：訊息不會重複發送

**問題**: 三個 Pod 都訂閱了 `sse:broadcast`，會不會導致同一個玩家收到 3 次訊息？

**答案**: ❌ **不會重複發送**

#### 廣播推送流程詳解

```
後端 API 發送廣播請求
    ↓
任一 SSE Pod 接收請求 (假設是 Pod-1)
    ↓
Pod-1 發布訊息到 Redis Pub/Sub (sse:broadcast)
    ↓
    ├─→ Pod-1 收到廣播 ────→ 推送給本地連接池的玩家 (Player 1, 2, 3)
    ├─→ Pod-2 收到廣播 ────→ 推送給本地連接池的玩家 (Player 4, 5, 6)
    └─→ Pod-3 收到廣播 ────→ 推送給本地連接池的玩家 (Player 7, 8, 9)

結果: 每個玩家只收到 1 次訊息 ✅
```

**為什麼不會重複？**

1. **玩家連接唯一性**: 每個玩家的 SSE 連接只會存在於**一個 Pod** 的本地連接池中
2. **本地推送**: 每個 Pod 只推送給**自己本地連接池**的玩家
3. **路由隔離**: Pod-1 無法訪問 Pod-2、Pod-3 的連接池

**範例**:
```go
// Pod-1 的本地連接池
connections = {
    "player_001": writer_001,
    "player_002": writer_002,
    "player_003": writer_003,
}

// Pod-2 的本地連接池
connections = {
    "player_004": writer_004,
    "player_005": writer_005,
}

// 當 Pod-1 收到廣播訊息時，只會推送給 player_001, player_002, player_003
// 當 Pod-2 收到廣播訊息時，只會推送給 player_004, player_005
// player_001 不會收到來自 Pod-2 的推送，因為 Pod-2 的連接池裡沒有 player_001
```

---

#### 個別推送流程詳解

```
後端 API 發送個別推送請求 (player_ids: [player_001, player_004])
    ↓
任一 SSE Pod 接收請求 (假設是 Pod-1)
    ↓
Pod-1 處理每個玩家:

    player_001:
      查詢路由表 → player_001 在 Pod-1
      ↓
      直接推送給本地連接 ✅

    player_004:
      查詢路由表 → player_004 在 Pod-2
      ↓
      發布到 Redis Pub/Sub (sse:pod:2)
      ↓
      Pod-2 收到訊息
      ↓
      Pod-2 推送給 player_004 ✅

結果: 每個玩家只收到 1 次訊息 ✅
```

**為什麼不會重複？**

1. **路由表查詢**: 通過 Redis Hash `sse:player_routes` 查詢玩家所在 Pod
2. **精確路由**: 訊息只會發送到玩家**實際連接**的那個 Pod
3. **單次推送**: 每個玩家只會被推送一次

**路由表範例**:
```redis
HGETALL sse:player_routes
1) "player_001"
2) "pod-1"
3) "player_002"
4) "pod-1"
5) "player_003"
6) "pod-1"
7) "player_004"
8) "pod-2"
9) "player_005"
10) "pod-2"
```

#### 玩家連接註冊機制

**確保唯一性的關鍵**:

```go
// 玩家連接時 (在任一 Pod 上)
func (m *sseManager) RegisterConnection(ctx context.Context, playerID string, writer inbound.SSEWriter) error {
    // 1. 加入本 Pod 的本地連接池
    m.connections[playerID] = writer

    // 2. 更新全局路由表 (覆蓋舊值，確保唯一性)
    m.redisClient.HSet(ctx, "sse:player_routes", playerID, m.podID)

    // 3. 增加線上計數
    m.redisClient.Incr(ctx, "sse:online_count")
}
```

**情境分析**:

| 情境 | 處理方式 | 結果 |
|------|---------|------|
| 玩家首次連接到 Pod-1 | 註冊到 Pod-1，路由表記錄 Pod-1 | ✅ 正常 |
| 玩家斷線後重連到 Pod-2 | 註冊到 Pod-2，路由表**覆蓋**為 Pod-2 | ✅ 訊息正確路由到 Pod-2 |
| 玩家同時打開兩個視窗 | 後打開的連接會覆蓋路由表 | ⚠️ 只有最新連接收到訊息 |

**結論**:
- ✅ 正常使用下，每個玩家只會在一個 Pod 上有連接
- ✅ 即使異常情況（多視窗），也只會推送到最新的連接，不會重複
- ✅ 路由表的覆蓋機制確保了唯一性

```go
    if len(req.PlayerIDs) > consts.MaxPlayerIDsPerRequest {
        return nil, fmt.Errorf("player_ids exceeds maximum limit of %d", consts.MaxPlayerIDsPerRequest)
    }

    sendID := uuid.New().String()
    now := time.Now()

    // 2. 創建通知實體（純記憶體對象，不持久化）
    notification := &entity.SSENotification{
        ID:        uuid.New().String(), // 每位玩家使用相同訊息，不同 ID 用於去重
        Title:     req.Title,
        Message:   req.Message,
        Type:      req.Type,
        Priority:  req.Priority,
        IconURL:   req.IconURL,
        ActionURL: req.ActionURL,
        CreatedAt: now,
        ExpiresAt: req.ExpiryAt,
    }

    // 3. 批次推送給目標玩家（透過 SSE Manager）
    queuedCount, err := uc.sseManager.SendToPlayers(ctx, req.PlayerIDs, notification)
    if err != nil {
        uc.logger.ErrorWithContext(ctx, "failed to send to players",
            uc.logger.Error("err", err),
            uc.logger.String("send_id", sendID))
        return nil, fmt.Errorf("send to players: %w", err)
    }

    // 4. 記錄審計日誌到 KDS
    uc.eventService.PublishEvent(ctx, "notification.send", map[string]interface{}{
        "send_id":      sendID,
        "merchant_id":  req.GlobalMerchantID,
        "player_count": len(req.PlayerIDs),
        "queued_count": queuedCount,
        "type":         notification.Type,
        "priority":     notification.Priority,
        "timestamp":    now.Unix(),
    })

    // 5. 返回回應
    return &dto.SendNotificationResponse{
        SendID:      sendID,
        PlayerCount: len(req.PlayerIDs),
        QueuedCount: queuedCount,
        SentAt:      now,
        Status:      consts.NotificationStatusQueued,
    }, nil

// StreamNotifications SSE 長連接實現（簡化版）
func (uc *sseNotificationUseCase) StreamNotifications(
    ctx context.Context,
    playerID string,
    writer inbound.SSEWriter,
) error {
    // 1. 註冊連接
    if err := uc.sseManager.RegisterConnection(ctx, playerID, writer); err != nil {
        return fmt.Errorf("register connection: %w", err)
    }
    defer uc.sseManager.UnregisterConnection(ctx, playerID)

    // 2. 發送歡迎訊息
    writer.Write("connected", map[string]interface{}{
        "player_id": playerID,
        "timestamp": time.Now(),
    })

    // 3. 發送離線訊息
    offlineMessages, err := uc.sseManager.GetOfflineMessages(ctx, playerID)
    if err != nil {
        uc.logger.ErrorWithContext(ctx, "failed to get offline messages",
            uc.logger.Error("err", err),
            uc.logger.String("player_id", playerID))
    } else {
        for _, msg := range offlineMessages {
            writer.Write("notification", msg)
        }
        // 清除已發送的離線訊息
        uc.sseManager.ClearOfflineMessages(ctx, playerID)
    }

    // 4. 保持連接（等待 context 取消）
    <-ctx.Done()

    return nil
}
```

```go
// GinSSEWriter Gin SSE Writer 實作
type GinSSEWriter struct {
    writer  gin.ResponseWriter
    flusher http.Flusher
    ctx     *gin.Context
}

// NewGinSSEWriter 創建 Gin SSE Writer
func NewGinSSEWriter(writer gin.ResponseWriter, ctx *gin.Context) inbound.SSEWriter {
    flusher, ok := writer.(http.Flusher)
    if !ok {
        // 如果不支援 Flusher,使用 nil
        flusher = nil
    }

    return &GinSSEWriter{
        writer:  writer,
        flusher: flusher,
        ctx:     ctx,
    }
}

// Write 寫入 SSE 事件
func (w *GinSSEWriter) Write(event string, data interface{}) error {
    // 將資料序列化為 JSON
    jsonData, err := json.Marshal(data)
    if err != nil {
        return fmt.Errorf("marshal data: %w", err)
    }

    // 寫入 SSE 格式
    // event: <event_name>
    // data: <json_data>
    // \n
    if _, err := fmt.Fprintf(w.writer, "event: %s\n", event); err != nil {
        return fmt.Errorf("write event: %w", err)
    }

    if _, err := fmt.Fprintf(w.writer, "data: %s\n\n", string(jsonData)); err != nil {
        return fmt.Errorf("write data: %w", err)
    }

    // 立即刷新緩衝區
    return w.Flush()
}

// Flush 刷新緩衝區
func (w *GinSSEWriter) Flush() error {
    if w.flusher != nil {
        w.flusher.Flush()
    }
    return nil
}

// Close 關閉連接
func (w *GinSSEWriter) Close() error {
    // Gin 的連接由框架管理,這裡不需要特別關閉
    return nil
```

```go
) ([]*entity.SSENotification, int64, error) {
    var notifications []*entity.SSENotification
    var total int64

    query := r.db.WithContext(ctx).
        Where("player_id = ?", playerID).
        Where("expires_at > ?", time.Now())

    // 查詢總數
    if err := query.Model(&entity.SSENotification{}).Count(&total).Error; err != nil {
        return nil, 0, fmt.Errorf("count notifications: %w", err)
    }

    // 分頁查詢
    offset := (page - 1) * pageSize
    err := query.
        Order("created_at DESC").
        Limit(pageSize).
        Offset(offset).
        Find(&notifications).Error

    if err != nil {
        return nil, 0, fmt.Errorf("find notifications: %w", err)
    }

    return notifications, total, nil
}

// IncrementStats 增量更新統計資訊 (使用 UPSERT)
func (r *sseNotificationRepository) IncrementStats(
    ctx context.Context,
    date, notifType, priority string,
    sent, delivered int64,
) error {
    // 使用 GORM 的 Clauses 實現 UPSERT
    stat := &entity.NotificationStats{
        Date:           date,
        Type:           notifType,
        Priority:       priority,
        TotalSent:      sent,
        TotalDelivered: delivered,
        CreatedAt:      time.Now(),
        UpdatedAt:      time.Now(),
    }

    return r.db.WithContext(ctx).
        Exec(`
            INSERT INTO sse_notification_stats
            (date, type, priority, total_sent, total_delivered, created_at, updated_at)
            VALUES (?, ?, ?, ?, ?, ?, ?)
            ON DUPLICATE KEY UPDATE
            total_sent = total_sent + VALUES(total_sent),
            total_delivered = total_delivered + VALUES(total_delivered),
            updated_at = VALUES(updated_at)
        `,
            stat.Date,
            stat.Type,
            stat.Priority,
            stat.TotalSent,
            stat.TotalDelivered,
            stat.CreatedAt,
            stat.UpdatedAt,
        ).Error
}
```

```go
package service

import (
    "context"
    "encoding/json"
    "fmt"

type sseManager struct {
    connections map[string]inbound.SSEWriter // playerID -> SSEWriter
    mu          sync.RWMutex                 // 連接池讀寫鎖
    redisClient *redis.Client                // Redis 客戶端

// NewSSEManager 創建 SSE 管理器
func NewSSEManager(
    redisClient *redis.Client,
    logger infrastructure.Logger,

    return &sseManager{

// ========== 連接管理 ==========

// RegisterConnection 註冊玩家 SSE 連接
func (m *sseManager) RegisterConnection(ctx context.Context, playerID string, writer inbound.SSEWriter) error {
    m.mu.Lock()
    defer m.mu.Unlock()

    // 加入本地連接池
    m.connections[playerID] = writer

    // 註冊到 Redis (用於跨實例狀態同步)
    key := consts.RedisKeySSEOnlinePrefix + playerID
    if err := m.redisClient.Set(ctx, key, "1", 0).Err(); err != nil {
        m.logger.ErrorWithContext(ctx, "failed to register to redis",
            m.logger.Error("err", err),
            m.logger.String("player_id", playerID))
        return fmt.Errorf("redis set: %w", err)
    }

    m.logger.InfoWithContext(ctx, "player connected",
        m.logger.String("player_id", playerID))

    return nil
}

// UnregisterConnection 取消註冊玩家 SSE 連接
func (m *sseManager) UnregisterConnection(ctx context.Context, playerID string) error {
    m.mu.Lock()
    defer m.mu.Unlock()

    // 從本地連接池移除
    delete(m.connections, playerID)

    // 從 Redis 移除
    key := consts.RedisKeySSEOnlinePrefix + playerID
    if err := m.redisClient.Del(ctx, key).Err(); err != nil {
        m.logger.ErrorWithContext(ctx, "failed to unregister from redis",
            m.logger.Error("err", err),
            m.logger.String("player_id", playerID))
        return fmt.Errorf("redis del: %w", err)
    }

    m.logger.InfoWithContext(ctx, "player disconnected",
        m.logger.String("player_id", playerID))

    return nil
}

// IsPlayerOnline 檢查玩家是否在線
func (m *sseManager) IsPlayerOnline(ctx context.Context, playerID string) (bool, error) {
    // 先檢查本地連接池
    m.mu.RLock()
    _, existsLocal := m.connections[playerID]
    m.mu.RUnlock()

    if existsLocal {
        return true, nil
    }

    // 檢查 Redis (可能在其他實例上)
    key := consts.RedisKeySSEOnlinePrefix + playerID
    exists, err := m.redisClient.Exists(ctx, key).Result()
    if err != nil {
        return false, fmt.Errorf("redis exists: %w", err)
    }

    return exists > 0, nil
}

// GetOnlinePlayerCount 獲取線上玩家數量
func (m *sseManager) GetOnlinePlayerCount(ctx context.Context) (int, error) {
    // 使用 Redis SCAN 查詢所有線上玩家
    pattern := consts.RedisKeySSEOnlinePrefix + "*"
    var cursor uint64
    var count int

    for {
        keys, newCursor, err := m.redisClient.Scan(ctx, cursor, pattern, 100).Result()
        if err != nil {
            return 0, fmt.Errorf("redis scan: %w", err)
        }

        count += len(keys)
        cursor = newCursor

        if cursor == 0 {
            break
        }
    }

    return count, nil
}

// GetOnlinePlayerIDs 獲取所有線上玩家 ID 列表
func (m *sseManager) GetOnlinePlayerIDs(ctx context.Context) ([]string, error) {
    pattern := consts.RedisKeySSEOnlinePrefix + "*"
    var cursor uint64
    var playerIDs []string

    for {
        keys, newCursor, err := m.redisClient.Scan(ctx, cursor, pattern, 100).Result()
        if err != nil {
            return nil, fmt.Errorf("redis scan: %w", err)
        }

        // 提取 playerID (移除 prefix)
        prefix := consts.RedisKeySSEOnlinePrefix
        for _, key := range keys {
            playerID := key[len(prefix):]
            playerIDs = append(playerIDs, playerID)
        }

        cursor = newCursor
        if cursor == 0 {
            break
        }
    }

    return playerIDs, nil
}

// ========== 訊息推送 ==========

// BroadcastToAll 廣播推送給所有線上玩家
func (m *sseManager) BroadcastToAll(ctx context.Context, notification *entity.SSENotification) (int, error) {
    m.mu.RLock()
    defer m.mu.RUnlock()

    successCount := 0

    // 遍歷本地連接池廣播
    for playerID, writer := range m.connections {
        if err := writer.Write("notification", notification); err != nil {
            m.logger.WarnWithContext(ctx, "failed to send to player",
                m.logger.Error("err", err),
                m.logger.String("player_id", playerID),
                m.logger.String("notification_id", notification.ID))
            continue
        }
        successCount++
    }

    m.logger.InfoWithContext(ctx, "broadcast completed",
        m.logger.Int("total_players", len(m.connections)),
        m.logger.Int("success_count", successCount),
        m.logger.String("notification_id", notification.ID))

    return successCount, nil
}

// SendToPlayer 推送給單一玩家
func (m *sseManager) SendToPlayer(ctx context.Context, playerID string, notification *entity.SSENotification) error {
    m.mu.RLock()
    writer, exists := m.connections[playerID]
    m.mu.RUnlock()

    if !exists {
        return fmt.Errorf("player not connected: %s", playerID)
    }

    if err := writer.Write("notification", notification); err != nil {
        return fmt.Errorf("write notification: %w", err)
    }

    return nil
}

// SendToPlayers 批次推送給多位玩家
func (m *sseManager) SendToPlayers(ctx context.Context, playerIDs []string, notification *entity.SSENotification) (int, error) {
    m.mu.RLock()
    defer m.mu.RUnlock()

    successCount := 0

    for _, playerID := range playerIDs {
        writer, exists := m.connections[playerID]
        if !exists {
            continue
        }

        if err := writer.Write("notification", notification); err != nil {
            m.logger.WarnWithContext(ctx, "failed to send to player",
                m.logger.Error("err", err),
                m.logger.String("player_id", playerID))
            continue
        }

        successCount++
    }

    return successCount, nil
}

// ========== 離線訊息管理 ==========

// EnqueueOfflineMessage 將訊息加入離線佇列 (Redis Streams)
func (m *sseManager) EnqueueOfflineMessage(ctx context.Context, playerID string, notification *entity.SSENotification) error {
    key := consts.RedisKeySSEOfflinePrefix + playerID

    // 序列化通知為 JSON
    data, err := json.Marshal(notification)
    if err != nil {
        return fmt.Errorf("marshal notification: %w", err)
    }

    // 使用 Redis Streams 儲存
    _, err = m.redisClient.XAdd(ctx, &redis.XAddArgs{
        Stream: key,
        MaxLen: 100, // 最多保留 100 條離線訊息
        Values: map[string]interface{}{
            "notification": string(data),
            "created_at":   time.Now().Unix(),
        },
    }).Result()

    if err != nil {
        return fmt.Errorf("redis xadd: %w", err)
    }

    // 設置 TTL (7 天)
    m.redisClient.Expire(ctx, key, consts.OfflineMessageTTL)

    return nil
}

// GetOfflineMessages 獲取玩家的離線訊息
func (m *sseManager) GetOfflineMessages(ctx context.Context, playerID string) ([]*entity.SSENotification, error) {
    key := consts.RedisKeySSEOfflinePrefix + playerID

    // 讀取所有離線訊息
    messages, err := m.redisClient.XRange(ctx, key, "-", "+").Result()
    if err != nil {
        return nil, fmt.Errorf("redis xrange: %w", err)
    }

    var notifications []*entity.SSENotification

    for _, msg := range messages {
        dataStr, ok := msg.Values["notification"].(string)
        if !ok {
            continue
        }

        var notification entity.SSENotification
        if err := json.Unmarshal([]byte(dataStr), &notification); err != nil {
            m.logger.WarnWithContext(ctx, "failed to unmarshal offline message",
                m.logger.Error("err", err))
            continue
        }

        notifications = append(notifications, &notification)
    }

    return notifications, nil
}

// ClearOfflineMessages 清除玩家的離線訊息
func (m *sseManager) ClearOfflineMessages(ctx context.Context, playerID string) error {
    key := consts.RedisKeySSEOfflinePrefix + playerID
    return m.redisClient.Del(ctx, key).Err()
}
```

```go
    }
```

### 5. 連接負載均衡策略 ⭐ **關鍵設計決策**

#### 問題分析：連接分布不均的風險

**潛在問題**：如果不妥善設計負載均衡策略，可能導致：

```
❌ 負載嚴重不均的情況：
┌────────────────────────────────────┐
│ Pod-1: 18,000 連接 (90% 負載) 🔥   │  ← NAT 網段 A 的玩家
│ Pod-2:  1,500 連接 (7.5% 負載)     │  ← 零星玩家
│ Pod-3:    500 連接 (2.5% 負載)     │  ← 零星玩家
└────────────────────────────────────┘
總計: 20,000 連接，但分布極不均勻
```

**根本原因**：

1. **Session Affinity (ClientIP)** 會將相同 IP 的請求路由到同一 Pod
2. 許多玩家來自**同一 NAT 網段**（公司、校園、咖啡廳）
3. 同一 NAT 網段的玩家有相同的 Public IP
4. 結果：大量玩家被路由到同一個 Pod

---

#### 負載均衡策略對比

| 策略 | 優點 | 缺點 | 適用場景 | 推薦度 |
|------|------|------|---------|--------|
| **輪詢 (Round Robin)** | - 負載最均勻<br>- 實作簡單<br>- K8s 預設支援 | - 跨 Pod 路由稍多<br>(已通過 Redis Pub/Sub 解決) | SSE 長連接服務 | ⭐⭐⭐⭐⭐ |
| **最少連接 (Least Conn)** | - 自動平衡負載<br>- 動態調整 | - 需要 Nginx Plus<br>或 HAProxy | 高階負載均衡需求 | ⭐⭐⭐⭐ |
| **IP Hash** | - 同玩家固定 Pod<br>- 減少跨 Pod 路由 | - NAT 網段問題<br>- **負載極不均** | ❌ 不適合 SSE | ⭐ |
| **Session Affinity** | - 同 IP 固定 Pod | - 同 IP Hash 問題 | ❌ 不適合 SSE | ⭐ |
| **隨機 (Random)** | - 負載均勻<br>- 實作簡單 | - 可能有輕微波動 | 簡單場景 | ⭐⭐⭐⭐ |

---

#### ✅ 推薦配置：輪詢負載均衡

**Kubernetes Service 配置**：
```yaml
spec:
  sessionAffinity: None  # 不使用 Session Affinity
```

**Nginx Ingress 配置**：
```yaml
metadata:
  annotations:
    # 不設定 upstream-hash-by，使用預設輪詢
    # ❌ nginx.ingress.kubernetes.io/upstream-hash-by: "$remote_addr"
```

**預期效果**：
```
✅ 負載均勻分布：
┌────────────────────────────────────┐
│ Pod-1: 6,800 連接 (34% 負載)       │
│ Pod-2: 6,500 連接 (32.5% 負載)     │
│ Pod-3: 6,700 連接 (33.5% 負載)     │
└────────────────────────────────────┘
總計: 20,000 連接，分布均勻 ±5%
```

#### HPA 配合負載均衡

**基於連接數的自動擴展**：

```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: sse-service-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: sse-service
  minReplicas: 3
  maxReplicas: 20
  metrics:
  # 基於每個 Pod 的平均連接數擴展
  - type: Pods
    pods:
      metric:
        name: sse_connections_per_pod
      target:
        type: AverageValue
        averageValue: "8000"  # 每個 Pod 8000 連接時觸發擴展
```

**擴展流程**：

```
當前: 3 Pods × 8000 連接 = 24,000 總連接
  ↓
連接數持續增長
  ↓
觸發 HPA: 平均連接數 > 8000
  ↓
擴展到 4 Pods
  ↓
新連接通過輪詢均勻分配到 4 個 Pod
  ↓
每個 Pod: ~6000 連接 (24,000 ÷ 4)
```

**關鍵優勢**：
- ✅ 輪詢確保新連接分配到所有 Pod（包括新擴展的 Pod）
- ✅ 自動平衡負載
- ✅ 無需手動干預

- ✅ **監控層 (Prometheus)**：持續監控連接分布，及時發現問題

**驗收標準**：
- 任意兩個 Pod 的連接數差異 < 20%
- 連接數標準差 < 平均值的 15%
- HPA 能正常觸發並均勻分配新連接

**廣播推送實作 (Phase 2)**:

```go
// BroadcastToAll 廣播推送給所有線上玩家 (Phase 2 版本)
func (m *sseManager) BroadcastToAll(ctx context.Context, notification *entity.SSENotification) (int, error) {
    // 序列化通知
    data, err := json.Marshal(notification)
    if err != nil {
        return 0, fmt.Errorf("marshal notification: %w", err)
    }

    // 發布到廣播 Channel (所有 Pod 都會收到)
    if err := m.redisClient.Publish(ctx, "sse:broadcast", data).Err(); err != nil {
        m.logger.ErrorWithContext(ctx, "failed to publish broadcast",
            m.logger.Error("err", err),
            m.logger.String("notification_id", notification.ID))
        return 0, fmt.Errorf("publish broadcast: %w", err)
    }

    // 統計總線上人數 (跨所有 Pod)
    totalOnline, _ := m.GetOnlinePlayerCount(ctx)

    m.logger.InfoWithContext(ctx, "broadcast published",
        m.logger.String("notification_id", notification.ID),
        m.logger.Int("total_online_players", totalOnline))

    return totalOnline, nil
}

// broadcastToLocalConnections 廣播到本地連接 (內部方法)
func (m *sseManager) broadcastToLocalConnections(notification *entity.SSENotification) int {
    m.mu.RLock()
    defer m.mu.RUnlock()

    successCount := 0
    for playerID, writer := range m.connections {
        if err := writer.Write("notification", notification); err != nil {
            m.logger.Warn("failed to send to player",
                m.logger.Error("err", err),
                m.logger.String("player_id", playerID))
            continue
        }
        successCount++
    }

    return successCount
}
```

**個別推送實作 (Phase 2)**:
```go
// SendToPlayer 推送給單一玩家 (Phase 2 版本)
func (m *sseManager) SendToPlayer(ctx context.Context, playerID string, notification *entity.SSENotification) error {
    // 1. 查詢玩家所在 Pod
    targetPodID, err := m.redisClient.HGet(ctx, "sse:player_routes", playerID).Result()
    if err == redis.Nil {
        // 玩家不在線,加入離線佇列
        return m.EnqueueOfflineMessage(ctx, playerID, notification)
    }
    if err != nil {
        return fmt.Errorf("get player route: %w", err)
    }

    // 2. 如果玩家在本 Pod,直接推送
    if targetPodID == m.podID {
        m.mu.RLock()
        writer, exists := m.connections[playerID]
        m.mu.RUnlock()

        if !exists {
            // 路由表過期,清理並加入離線佇列
            m.redisClient.HDel(ctx, "sse:player_routes", playerID)
            return m.EnqueueOfflineMessage(ctx, playerID, notification)
        }

        if err := writer.Write("notification", notification); err != nil {
            return fmt.Errorf("write notification: %w", err)
        }
        return nil
    }

    // 3. 玩家在其他 Pod,透過 Pub/Sub 路由
    message := map[string]interface{}{
        "player_id":    playerID,
        "notification": notification,
    }

    data, err := json.Marshal(message)
    if err != nil {
        return fmt.Errorf("marshal message: %w", err)
    }

    // 發布到目標 Pod 專屬 Channel
    channel := fmt.Sprintf("sse:pod:%s", targetPodID)
    if err := m.redisClient.Publish(ctx, channel, data).Err(); err != nil {
        return fmt.Errorf("publish to pod: %w", err)
    }

    m.logger.InfoWithContext(ctx, "routed to target pod",
        m.logger.String("player_id", playerID),
        m.logger.String("target_pod", targetPodID))

    return nil
}
```

**Pub/Sub 監聽器**:
```go
// startPubSubListener 啟動 Pub/Sub 訊息監聽 (Phase 2)
func (m *sseManager) startPubSubListener(ctx context.Context) {
    // 訂閱廣播 Channel 和本 Pod Channel
    m.pubsub = m.redisClient.Subscribe(ctx,
        "sse:broadcast",                   // 廣播 Channel
        fmt.Sprintf("sse:pod:%s", m.podID), // 本 Pod Channel
    )
    defer m.pubsub.Close()

    ch := m.pubsub.Channel()

    m.logger.Info("Pub/Sub listener started",
        m.logger.String("pod_id", m.podID))

    for msg := range ch {
        switch msg.Channel {
        case "sse:broadcast":
            // 處理廣播訊息
            m.handleBroadcastMessage(msg.Payload)

        case fmt.Sprintf("sse:pod:%s", m.podID):
            // 處理個別推送訊息
            m.handleTargetedMessage(msg.Payload)
        }
    }
}

// handleBroadcastMessage 處理廣播訊息
func (m *sseManager) handleBroadcastMessage(payload string) {
    var notification entity.SSENotification
    if err := json.Unmarshal([]byte(payload), &notification); err != nil {
        m.logger.Error("failed to unmarshal broadcast",
            m.logger.Error("err", err))
        return
    }

    // 廣播到本地所有連接
    count := m.broadcastToLocalConnections(&notification)

    m.logger.Info("broadcast delivered to local connections",
        m.logger.String("notification_id", notification.ID),
        m.logger.Int("local_count", count))
}

// handleTargetedMessage 處理目標推送訊息
func (m *sseManager) handleTargetedMessage(payload string) {
    var message struct {
        PlayerID     string                  `json:"player_id"`
        Notification entity.SSENotification `json:"notification"`
    }

    if err := json.Unmarshal([]byte(payload), &message); err != nil {
        m.logger.Error("failed to unmarshal targeted message",
            m.logger.Error("err", err))
        return
    }

    // 推送到本地連接
    m.mu.RLock()
    writer, exists := m.connections[message.PlayerID]
    m.mu.RUnlock()

    if !exists {
        m.logger.Warn("player not found in local connections",
            m.logger.String("player_id", message.PlayerID))
        return
    }

    if err := writer.Write("notification", &message.Notification); err != nil {
        m.logger.Error("failed to write notification",
            m.logger.Error("err", err),
            m.logger.String("player_id", message.PlayerID))
    }
}
```

#### 5.3 玩家路由表管理

**連接註冊 (Phase 2)**:
```go
// RegisterConnection 註冊玩家 SSE 連接 (Phase 2 版本)
func (m *sseManager) RegisterConnection(ctx context.Context, playerID string, writer inbound.SSEWriter) error {
    m.mu.Lock()
    defer m.mu.Unlock()

    // 1. 加入本地連接池
    m.connections[playerID] = writer

    // 2. 註冊到 Redis 路由表 (記錄玩家在哪個 Pod)
    if err := m.redisClient.HSet(ctx, "sse:player_routes", playerID, m.podID).Err(); err != nil {
        m.logger.ErrorWithContext(ctx, "failed to register player route",
            m.logger.Error("err", err),
            m.logger.String("player_id", playerID))
        return fmt.Errorf("redis hset: %w", err)
    }

    // 3. 增加線上計數器
    if err := m.redisClient.Incr(ctx, "sse:online_count").Err(); err != nil {
        m.logger.ErrorWithContext(ctx, "failed to increment online count",
            m.logger.Error("err", err))
    }

    // 4. 更新 Pod 連接數統計
    podConnKey := fmt.Sprintf("sse:pod_stats:%s", m.podID)
    m.redisClient.Set(ctx, podConnKey, len(m.connections), 0)

    m.logger.InfoWithContext(ctx, "player connected",
        m.logger.String("player_id", playerID),
        m.logger.String("pod_id", m.podID),
        m.logger.Int("local_connections", len(m.connections)))

    return nil
}

// UnregisterConnection 取消註冊玩家 SSE 連接 (Phase 2 版本)
func (m *sseManager) UnregisterConnection(ctx context.Context, playerID string) error {
    m.mu.Lock()
    defer m.mu.Unlock()

    // 1. 從本地連接池移除
    delete(m.connections, playerID)

    // 2. 從 Redis 路由表移除
    if err := m.redisClient.HDel(ctx, "sse:player_routes", playerID).Err(); err != nil {
        m.logger.ErrorWithContext(ctx, "failed to unregister player route",
            m.logger.Error("err", err),
            m.logger.String("player_id", playerID))
    }

    // 3. 減少線上計數器
    if err := m.redisClient.Decr(ctx, "sse:online_count").Err(); err != nil {
        m.logger.ErrorWithContext(ctx, "failed to decrement online count",
            m.logger.Error("err", err))
    }

    // 4. 更新 Pod 連接數統計
    podConnKey := fmt.Sprintf("sse:pod_stats:%s", m.podID)
    m.redisClient.Set(ctx, podConnKey, len(m.connections), 0)

    m.logger.InfoWithContext(ctx, "player disconnected",
        m.logger.String("player_id", playerID),
        m.logger.String("pod_id", m.podID),
        m.logger.Int("local_connections", len(m.connections)))

    return nil
}
```

```go
// GetPodStats 獲取各 Pod 連接統計 (Phase 2 新增)
func (m *sseManager) GetPodStats(ctx context.Context) (map[string]int, error) {
    pattern := "sse:pod_stats:*"
    stats := make(map[string]int)

    var cursor uint64
    for {
        keys, newCursor, err := m.redisClient.Scan(ctx, cursor, pattern, 100).Result()
        if err != nil {
            return nil, fmt.Errorf("redis scan: %w", err)
        }

        for _, key := range keys {
            count, _ := m.redisClient.Get(ctx, key).Int()
            podID := strings.TrimPrefix(key, "sse:pod_stats:")
            stats[podID] = count
        }

        cursor = newCursor
        if cursor == 0 {
            break
        }
    }

    return stats, nil
}
```

**Pod 關閉時的處理**:

```go
// Shutdown 優雅關閉 SSE Manager (Phase 2)
func (m *sseManager) Shutdown(ctx context.Context) error {
    m.logger.Info("Starting graceful shutdown",
        m.logger.String("pod_id", m.podID))

    m.mu.Lock()
    defer m.mu.Unlock()

    // 1. 停止接受新連接 (由 HTTP Server 處理)

    // 2. 通知所有連接的玩家即將斷線
    shutdownNotification := &entity.SSENotification{
        ID:       uuid.New().String(),
        Title:    "系統維護",
        Message:  "連接即將斷開，請稍後重新連接",
        Type:     "system",
        Priority: "high",
    }

    for playerID, writer := range m.connections {
        writer.Write("shutdown", shutdownNotification)

        // 清理路由表
        m.redisClient.HDel(ctx, "sse:player_routes", playerID)
    }

    // 3. 等待客戶端自動重連到其他 Pod
    time.Sleep(5 * time.Second)

    // 4. 強制關閉所有連接
    for playerID, writer := range m.connections {
        writer.Close()
        m.logger.Info("connection closed",
            m.logger.String("player_id", playerID))
    }

    // 5. 清空連接池
    m.connections = make(map[string]inbound.SSEWriter)

    // 6. 關閉 Pub/Sub 訂閱
    if m.pubsub != nil {
        m.pubsub.Close()
    }

    // 7. 清理 Pod 統計
    podConnKey := fmt.Sprintf("sse:pod_stats:%s", m.podID)
    m.redisClient.Del(ctx, podConnKey)

    m.logger.Info("Graceful shutdown completed",
        m.logger.String("pod_id", m.podID))

    return nil
}
```

```javascript
// 前端 SSE 客戶端自動重連
class SSEClient {
    constructor(url, token) {
        this.url = url;
        this.token = token;
        this.eventSource = null;
        this.reconnectInterval = 1000; // 初始重連間隔
        this.maxReconnectInterval = 30000; // 最大重連間隔
    }

    connect() {
        this.eventSource = new EventSource(`${this.url}?token=${this.token}`);

        this.eventSource.addEventListener('notification', (e) => {
            const notification = JSON.parse(e.data);
            this.handleNotification(notification);
        });

        this.eventSource.addEventListener('shutdown', (e) => {
            console.log('Server shutting down, will reconnect...');
            this.reconnect();
        });

        this.eventSource.onerror = () => {
            console.error('SSE connection error, reconnecting...');
            this.reconnect();
        };
    }

    reconnect() {
        if (this.eventSource) {
            this.eventSource.close();
        }

        setTimeout(() => {
            this.connect();
            // 指數退避
            this.reconnectInterval = Math.min(
                this.reconnectInterval * 2,
                this.maxReconnectInterval
            );
        }, this.reconnectInterval);
    }
}
```

## ⚠️ 注意事項與最佳實踐

### 1. Clean Architecture 合規性
- ✅ **Domain Layer**: 不依賴任何外層,純業務邏輯
- ✅ **Application Layer**: 只依賴 Domain,實作 UseCase
- ✅ **Adapter Layer**: 實作 Domain Ports 介面
- ✅ **Infrastructure Layer**: 提供技術實作細節

### 2. API 認證分離
- **後端 API** (`/admin/*`): 使用 API Key 認證
- **前端 API** (`/notifications/*`): 使用 JWT 認證
- 不同的 middleware 處理不同的認證機制

### 3. 錯誤處理規範
- 所有錯誤使用 `internal/domain/errmsg/errors.go` 定義
- 使用 `fmt.Errorf` 包裝錯誤,保留錯誤鏈
- 日誌記錄使用 `infrastructure.Logger`
- HTTP 錯誤統一使用 `response` 工具包

### 4. 測試策略
- **單元測試**: UseCase 層 100% 覆蓋
- **Mock 測試**: Repository 層使用 testify/mock
- **整合測試**: Handler 層整合測試
- **壓力測試**: wrk/ab 效能測試

### 5. 效能目標
| 指標 | 目標 | 驗收標準 |
|------|------|----------|
| 廣播吞吐量 | > 10,000 QPS | wrk 測試 |
| 訊息入隊延遲 | < 100ms (P99) | 壓力測試 |
| 並發連接數 | 10,000+ | SSE 連接測試 |
| 訊息遞送率 | 99% | 統計資料驗證 |

### 6. 安全性要求
- ✅ API Key 驗證正確實施
- ✅ JWT Token 驗證與過期處理
- ✅ 所有推播事件記錄至 KDS (審計日誌)
- ✅ 敏感操作記錄完整
- ✅ 實施速率限制 (防止濫用)

### 7. 監控與告警
- **關鍵指標**:
  - 線上玩家數
  - 訊息推送成功率
  - SSE 連接異常斷開率

### A. SSE Service Deployment

**檔案**: `k8s/sse-deployment.yaml`

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: sse-service
  namespace: notification
  labels:
    app: sse-service
    version: v1.0
spec:
  replicas: 3  # 初始 3 個 Pod
  selector:
    matchLabels:
      app: sse-service
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0  # 確保零停機
  template:
    metadata:
      labels:
        app: sse-service
        version: v1.0
    spec:
      containers:
      - name: sse-service
        image: your-registry/fat-notification-cat:latest
        command: ["./fat_notification_cat"]
        args: ["sse"]  # 新增 SSE 專用啟動模式

        env:
        - name: SSE_POD_ID
          valueFrom:
            fieldRef:
              fieldPath: metadata.name  # 使用 Pod 名稱作為 Pod ID
        - name: REDIS_ADDR
          value: "redis-service:6379"
        - name: MYSQL_DSN
          valueFrom:
            secretKeyRef:
              name: mysql-secret
              key: dsn
        - name: GOMAXPROCS
          value: "4"  # 調整 Go runtime 參數

        ports:
        - name: http
          containerPort: 8080
          protocol: TCP
        - name: metrics
          containerPort: 9090
          protocol: TCP

        resources:
          requests:
            cpu: "500m"
            memory: "512Mi"
          limits:
            cpu: "2000m"
            memory: "2Gi"

        # 健康檢查
        livenessProbe:
          httpGet:
            path: /health/live
            port: 8080
          initialDelaySeconds: 30
          periodSeconds: 10
          timeoutSeconds: 5
          failureThreshold: 3

        readinessProbe:
          httpGet:
            path: /health/ready
            port: 8080
          initialDelaySeconds: 10
          periodSeconds: 5
          timeoutSeconds: 3
          successThreshold: 1
          failureThreshold: 3

        # 優雅關閉
        lifecycle:
          preStop:
            exec:
              command: ["/bin/sh", "-c", "sleep 15"]  # 等待 15 秒讓連接遷移

      terminationGracePeriodSeconds: 30

      # 反親和性：避免所有 Pod 在同一節點
      affinity:
        podAntiAffinity:
          preferredDuringSchedulingIgnoredDuringExecution:
          - weight: 100
            podAffinityTerm:
              labelSelector:
                matchExpressions:
                - key: app
                  operator: In
                  values:
                  - sse-service
              topologyKey: kubernetes.io/hostname
```

### C. Service 配置

**檔案**: `k8s/sse-service.yaml`

```yaml
apiVersion: v1
kind: Service
metadata:
  name: sse-service
  namespace: notification
  labels:
    app: sse-service
spec:
  type: ClusterIP
  ports:
  - name: http
    port: 8080
    targetPort: 8080
    protocol: TCP
  - name: metrics
    port: 9090
    targetPort: 9090
    protocol: TCP
  selector:
    app: sse-service

  # ⭐ 負載均衡策略：不使用 Session Affinity
  # 理由：
  # 1. Session Affinity (ClientIP) 會導致來自同一 NAT 網段的玩家路由到同一 Pod
  # 2. 例如：公司網路、校園網路的玩家會集中在某個 Pod
  # 3. 造成負載嚴重不均（某個 Pod 可能有 20k 連接，其他 Pod 只有 2k）
  # 4. Redis Pub/Sub 已解決跨 Pod 路由問題，Session Affinity 不是必需的
  sessionAffinity: None  # 使用輪詢負載均衡（預設）

  # ❌ 不推薦使用（僅供參考）:
  # sessionAffinity: ClientIP
  # sessionAffinityConfig:
  #   clientIP:
  #     timeoutSeconds: 10800
```

### D. Ingress 配置（可選）

**檔案**: `k8s/sse-ingress.yaml`

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: sse-ingress
  namespace: notification
  annotations:
    kubernetes.io/ingress.class: nginx

    # SSE 長連接優化
    nginx.ingress.kubernetes.io/proxy-read-timeout: "3600"  # 1 小時超時
    nginx.ingress.kubernetes.io/proxy-send-timeout: "3600"
    nginx.ingress.kubernetes.io/proxy-buffering: "off"     # 禁用緩衝（SSE 必須）
    nginx.ingress.kubernetes.io/proxy-connect-timeout: "60"

    # ⭐ 負載均衡策略：輪詢（預設）
    # 不使用 upstream-hash-by，讓 Nginx 使用輪詢分配連接
    # 確保每個 Pod 的連接數均勻分布

    # ❌ 不推薦使用（會導致負載不均）:
    # nginx.ingress.kubernetes.io/upstream-hash-by: "$remote_addr"
    # nginx.ingress.kubernetes.io/upstream-hash-by: "$http_x_forwarded_for"

    # ✅ 可選：基於最少連接數的負載均衡（需要 Nginx Plus）
    # nginx.ingress.kubernetes.io/load-balance: "least_conn"

    # WebSocket/SSE 支援
    nginx.ingress.kubernetes.io/websocket-services: "sse-service"

spec:
  rules:
  - host: sse.notification.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: sse-service
            port:
              number: 8080
  tls:
  - hosts:
    - sse.notification.example.com
    secretName: sse-tls-secret
```

### G. PrometheusRule (告警規則)

**檔案**: `k8s/sse-prometheus-rule.yaml`

```yaml
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: sse-alerts
  namespace: notification
spec:
  groups:
  - name: sse-service
    interval: 30s
    rules:
    # SSE 連接數異常
    - alert: SSEConnectionsHigh
      expr: sse_connections_total > 45000
      for: 5m
      labels:
        severity: warning
      annotations:
        summary: "SSE 總連接數過高"
        description: "當前總連接數 {{ $value }}，接近系統上限"

    # 訊息推送失敗率高
    - alert: SSEMessageDeliveryFailed
      expr: rate(sse_message_failed_total[5m]) / rate(sse_message_sent_total[5m]) > 0.05
      for: 2m
      labels:
        severity: critical
      annotations:
        summary: "SSE 訊息推送失敗率過高"
        description: "失敗率 {{ $value | humanizePercentage }}，超過 5% 閾值"

    # Pod 重啟頻繁
    - alert: SSEPodRestartTooOften
      expr: rate(kube_pod_container_status_restarts_total{namespace="notification", pod=~"sse-service-.*"}[1h]) > 0.1
      for: 5m
      labels:
        severity: warning
      annotations:
        summary: "SSE Pod 重啟頻繁"
        description: "Pod {{ $labels.pod }} 在過去 1 小時重啟率過高"

    # Redis Pub/Sub 延遲高
    - alert: RedisPubSubLatencyHigh
      expr: histogram_quantile(0.99, rate(redis_pubsub_latency_seconds_bucket[5m])) > 0.1
      for: 5m
      labels:
        severity: warning
      annotations:
        summary: "Redis Pub/Sub 延遲過高"
        description: "P99 延遲 {{ $value }}s，超過 100ms 閾值"
```

### H. 部署腳本

**檔案**: `deploy-sse.sh`

```bash
#!/bin/bash

set -e

NAMESPACE="notification"
KUBECTL="kubectl"

echo "🚀 開始部署 SSE Service..."

# 1. 創建 Namespace (如果不存在)
$KUBECTL create namespace $NAMESPACE --dry-run=client -o yaml | $KUBECTL apply -f -

# 2. 應用 ConfigMap
echo "📝 應用 ConfigMap..."
$KUBECTL apply -f k8s/sse-configmap.yaml

# 3. 應用 Deployment
echo "🎯 部署 SSE Service Pods..."
$KUBECTL apply -f k8s/sse-deployment.yaml

# 4. 等待 Deployment 就緒
echo "⏳ 等待 Deployment 就緒..."
$KUBECTL rollout status deployment/sse-service -n $NAMESPACE --timeout=300s

# 5. 應用 Service
echo "🌐 創建 Service..."
$KUBECTL apply -f k8s/sse-service.yaml

# 6. 應用 HPA
echo "📊 配置 HPA..."
$KUBECTL apply -f k8s/sse-hpa.yaml

# 7. 應用 Ingress (可選)
if [ -f "k8s/sse-ingress.yaml" ]; then
    echo "🔗 配置 Ingress..."
    $KUBECTL apply -f k8s/sse-ingress.yaml
fi

# 8. 應用監控配置
echo "📈 配置監控..."
$KUBECTL apply -f k8s/sse-servicemonitor.yaml
$KUBECTL apply -f k8s/sse-prometheus-rule.yaml

# 9. 顯示部署狀態
echo ""
echo "✅ SSE Service 部署完成！"
echo ""
echo "📊 部署狀態:"
$KUBECTL get deployment,pods,svc,hpa -n $NAMESPACE -l app=sse-service

echo ""
echo "🔍 查看日誌:"
echo "  kubectl logs -f deployment/sse-service -n $NAMESPACE"
echo ""
echo "📈 查看監控:"
echo "  kubectl port-forward svc/sse-service 9090:9090 -n $NAMESPACE"
```
