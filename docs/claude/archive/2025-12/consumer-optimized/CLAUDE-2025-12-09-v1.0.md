## 🎯 專案概述

### **問題背景**
在 KDS Consumer 服務分析過程中發現了潛在的資源風險：
1. **無限制分片併發**: 每個分片都會創建獨立的 goroutine，當分片數量增加時會導致資源消耗線性增長
2. **記憶體消耗不可控**: 多分片場景下記憶體使用可能超過 Pod 限制導致 OOM
3. **CPU 資源競爭**: 大量併發 goroutine 導致 CPU 上下文切換開銷

### **觸發原因**
用戶詢問當前 Consumer 參數配置是否合理，在分析過程中發現 `consumer.go:110` 的分片處理邏輯存在併發控制缺失。

### **資源配置約束**
```yaml
resources:
  limits:
    cpu: 1000m     # 1 CPU core
    memory: 1Gi    # 1024 MB
  requests:
    cpu: 200m      # 0.2 CPU core  
    memory: 512Mi  # 512 MB
```

## 🔍 問題分析

### **風險評估 - 多分片場景**

#### **記憶體消耗估算**
```
分片數量對記憶體影響：
- 4 分片: 240-280MB (安全)
- 8 分片: 400-450MB (臨界)  
- 16 分片: 700-800MB (危險)
- 32 分片: 1200-1500MB (OOM風險)

每分片記憶體構成：
- KDS Records 緩衝: 5000 records × 2KB = 10MB
- Worker Pool 緩衝: 30 workers × 1000 × 2KB = 60MB  
- JSON 處理臨時對象: 20-30MB
```

#### **CPU 消耗分析**
```
併發 goroutine 數量：
- 分片 goroutines: N個 (N = 分片數)
- Worker goroutines: N × 30個
- 總計: N × 31個 goroutines

16 分片場景: 16 × 31 = 496 個 goroutines
32 分片場景: 32 × 31 = 992 個 goroutines
```

### **核心問題代碼**
```go
// ❌ 問題代碼: consumer.go:115-137
for shardId, iterator := range shards {
    shardWaiters.Add(1)
    // ... 分片鎖邏輯
    
    // 為每個分片創建一個協程 - 無併發限制！
    go k.consumeShardEvents(ctx, shardId, iterator, shardMutex, &shardWaiters, shardErrs)
}
```

## 🛠️ 解決方案設計

### **核心架構：信號量併發控制**

#### **設計原則**
1. **硬性併發限制**: 使用信號量控制最大併發分片數量
2. **優雅降級**: 當達到併發上限時跳過而非阻塞
3. **資源自動釋放**: 確保信號量許可在分片結束時正確釋放
4. **向後兼容**: 新增配置參數，不影響現有功能

#### **技術方案**
```go
// 信號量控制併發數量
shardSemaphore := make(chan struct{}, maxConcurrentShards)

// 嘗試獲取許可
select {
case shardSemaphore <- struct{}{}:
    // 獲得許可，創建 goroutine
    go k.consumeShardEventsWithSemaphore(...)
default:
    // 無法獲得許可，記錄並跳過
    k.logger.WarnWithContext(ctx, "Shard semaphore full, skipping shard")
}
```

### **2. 核心邏輯實現**
**修改文件**: `internal/infrastructure/kds/consumer.go`

#### **A. ConsumeAllEvents 方法優化**
```go
// ✅ 新增併發控制邏輯
func (k *KDSService) ConsumeAllEvents(ctx context.Context) error {
    shards, err := k.getShardIterators(ctx)
    if err != nil {
        return fmt.Errorf("failed to get shard iterators: %w", err)
    }

    // 計算併發限制
    maxConcurrentShards := k.config.Consumer.MaxShardConcurrency
    if maxConcurrentShards <= 0 {
        maxConcurrentShards = 8 // 預設值
    }
    if len(shards) < maxConcurrentShards {
        maxConcurrentShards = len(shards) // 不超過實際分片數
    }

    // 創建信號量
    shardSemaphore := make(chan struct{}, maxConcurrentShards)
    
    // 併發控制的分片處理
    for shardId, iterator := range shards {
        select {
        case shardSemaphore <- struct{}{}:
            // 獲得許可，創建 goroutine
            go k.consumeShardEventsWithSemaphore(
                ctx, shardId, iterator, shardMutex,
                &shardWaiters, shardErrs, shardSemaphore)
        case <-ctx.Done():
            // 上下文取消，退出
            return ctx.Err()
        default:
            // 併發已滿，記錄警告並跳過
            k.logger.WarnWithContext(ctx,
                "Shard semaphore full, skipping shard",
                k.logger.String("shard_id", shardId))
        }
    }
    
    // ... 等待邏輯保持不變
}
```

#### **B. 新增信號量控制方法**
```go
// ✅ 新增方法：帶信號量的分片處理
func (k *KDSService) consumeShardEventsWithSemaphore(
    ctx context.Context,
    shardId, initialIterator string,
    shardMutex infrastructure.DistributedMutex,
    shardWaiters *sync.WaitGroup,
    shardErrs chan<- error,
    semaphore chan struct{},
) {
    // 確保函數退出時釋放信號量
    defer func() {
        <-semaphore // 釋放許可
        k.logger.InfoWithContext(ctx, "Released shard semaphore permit",
            k.logger.String("shard_id", shardId))
    }()

    k.logger.InfoWithContext(ctx, "Acquired shard semaphore permit", 
        k.logger.String("shard_id", shardId))

    // 調用原有處理邏輯
    k.consumeShardEvents(ctx, shardId, initialIterator, shardMutex, shardWaiters, shardErrs)
}
```

### **3. 日誌增強**

## 🛡️ 風險評估與緩解

### **潛在風險**
1. **分片處理延遲**: 部分分片可能被跳過
2. **處理能力下降**: 併發限制可能降低總處理能力
3. **配置複雜性**: 新增配置參數增加複雜度

### **緩解策略**
1. **智能重試**: 被跳過的分片在下一輪會重新嘗試
2. **動態調整**: 支持運行時調整併發參數
3. **完整文檔**: 提供詳細的配置指南和監控說明

### **回滾計劃**
```yaml
# 緊急回滾：增大併發限制到與分片數相等
CONSUMER_MAX_SHARD_CONCURRENCY: "99"  # 實際上移除限制
```
