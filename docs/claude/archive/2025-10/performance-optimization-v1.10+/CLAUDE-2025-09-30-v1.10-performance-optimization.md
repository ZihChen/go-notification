# Campaign Target 關聯表正規化設計 v1.10+

## 問題分析

當前實作在 `ProcessPlayer` 方法中存在嚴重效能問題：

1. **JSON 解析開銷**：每次都要解析所有 campaign 的 `target_detail` JSON
2. **線性搜尋**：在大量 campaign 中逐一比對目標
3. **重複查詢**：相同的查詢邏輯重複執行

## 解決方案：關聯表正規化

### 1. 新增關聯表結構

```sql
-- Campaign Target 關聯表
CREATE TABLE `campaign_targets` (
  `id` bigint unsigned NOT NULL AUTO_INCREMENT,
  `campaign_id` bigint unsigned NOT NULL,
  `target_type` varchar(20) NOT NULL COMMENT 'player/level/tag/all',
  `target_id` varchar(100) NULL COMMENT '目標ID：player_account/level_id/tag_id，all類型為NULL',
  `created_at` timestamp NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_campaign_target` (`campaign_id`, `target_type`, `target_id`),
  KEY `idx_target_type_id` (`target_type`, `target_id`),
  KEY `idx_campaign_id` (`campaign_id`),
  CONSTRAINT `fk_campaign_targets_campaign` FOREIGN KEY (`campaign_id`) REFERENCES `message_campaigns` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='訊息活動目標關聯表';
```

### 2. 資料遷移策略

```go
// 遷移現有 target_detail 到關聯表
func MigrateCampaignTargets(ctx context.Context) error {
    campaigns, err := campaignRepo.FindAll(ctx)
    if err != nil {
        return err
    }
    
    for _, campaign := range campaigns {
        switch campaign.Target {
        case consts.TargetPlayer:
            var accounts []string
            json.Unmarshal([]byte(*campaign.TargetDetail), &accounts)
            for _, account := range accounts {
                campaignTargetRepo.Create(ctx, &entity.CampaignTarget{
                    CampaignID: campaign.ID,
                    TargetType: consts.TargetPlayer,
                    TargetID:   &account,
                })
            }
        case consts.TargetLevel:
            var levelIDs []string
            json.Unmarshal([]byte(*campaign.TargetDetail), &levelIDs)
            for _, levelID := range levelIDs {
                campaignTargetRepo.Create(ctx, &entity.CampaignTarget{
                    CampaignID: campaign.ID,
                    TargetType: consts.TargetLevel,
                    TargetID:   &levelID,
                })
            }
        case consts.TargetTag:
            var tagIDs []string
            json.Unmarshal([]byte(*campaign.TargetDetail), &tagIDs)
            for _, tagID := range tagIDs {
                campaignTargetRepo.Create(ctx, &entity.CampaignTarget{
                    CampaignID: campaign.ID,
                    TargetType: consts.TargetTag,
                    TargetID:   &tagID,
                })
            }
        case consts.TargetAll:
            campaignTargetRepo.Create(ctx, &entity.CampaignTarget{
                CampaignID: campaign.ID,
                TargetType: consts.TargetAll,
                TargetID:   nil,
            })
        }
    }
}
```

### 3. 高效能查詢實作

```go
// 新的高效能實作
func (u *MessageUseCase) ProcessPlayerV2(ctx context.Context, globalPlayerID string) error {
    // 獲取玩家資訊

    }
    
    // 批量處理 player_message 創建
    return u.processCampaignMessages(ctx, globalPlayerID, eligibleCampaignIDs)
}
```

### 4. Repository 最佳化查詢

```go
func (r *CampaignTargetRepository) FindCampaignIDsByPlayerCriteria(
    ctx context.Context,
    playerAccount string,
    levelID string,
    tagIDs []uint64,
    merchantID uint64,
) ([]uint64, error) {
    
    tagIDStrings := make([]string, len(tagIDs))
    for i, id := range tagIDs {
        tagIDStrings[i] = fmt.Sprintf("%d", id)
    }
    
    query := `
        SELECT DISTINCT ct.campaign_id 
        FROM campaign_targets ct
        INNER JOIN message_campaigns mc ON ct.campaign_id = mc.id
        WHERE mc.merchant_id = ? 
          AND mc.status IN ('scheduled', 'sent')
          AND mc.deleted_at IS NULL
          AND (
            (ct.target_type = 'all') OR
            (ct.target_type = 'player' AND ct.target_id = ?) OR
            (ct.target_type = 'level' AND ct.target_id = ?) OR
            (ct.target_type = 'tag' AND ct.target_id IN (?))
          )
    `
    
    var campaignIDs []uint64
    err := r.db.WithContext(ctx).Raw(query, merchantID, playerAccount, levelID, tagIDStrings).Scan(&campaignIDs).Error
    return campaignIDs, err
}
```

## 效能對比

### 🐌 原始實作
- **時間複雜度**：O(n × m) - n個campaigns × m個target_detail項目
- **空間複雜度**：O(n × m) - 需要解析所有JSON
- **IO操作**：N+1查詢問題

### 🚀 優化後實作
- **時間複雜度**：O(log n) - 基於索引的查詢
- **空間複雜度**：O(1) - 直接查詢結果
- **IO操作**：單次JOIN查詢

## 實施建議

### Phase 1: 漸進式遷移
1. 新增 `campaign_targets` 表
2. 在創建/更新 campaign 時同時寫入關聯表
3. 保持 `target_detail` 欄位作為fallback

### Phase 2: 效能優化
1. 實作新的查詢邏輯
2. A/B測試驗證效能提升
3. 監控查詢效能指標

### Phase 3: 完全遷移
1. 遷移所有歷史資料
2. 移除舊的JSON查詢邏輯
3. 可選：移除 `target_detail` 欄位

### 方案C: Redis 快取方案
將熱門查詢結果快取到 Redis：

```go
// Redis 快取實作
func (u *MessageUseCase) ProcessPlayerWithCache(ctx context.Context, globalPlayerID string) error {
    cacheKey := fmt.Sprintf("player_campaigns:%s", globalPlayerID)
    
    // 先嘗試從快取取得
    if campaignIDs, err := u.redis.SMembers(ctx, cacheKey).Result(); err == nil {
        return u.processCachedCampaigns(ctx, globalPlayerID, campaignIDs)
    }
    
    // 快取失效則重新計算並快取
    campaignIDs, err := u.calculateEligibleCampaigns(ctx, globalPlayerID)
    if err != nil {
        return err
    }
    
    // 快取結果 (TTL: 1小時)
    u.redis.SAdd(ctx, cacheKey, campaignIDs...)
    u.redis.Expire(ctx, cacheKey, time.Hour)
    
    return u.processCampaignMessages(ctx, globalPlayerID, campaignIDs)
}
```
