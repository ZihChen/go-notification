# 支援 Server-Sent Events 通知協定

## 功能概述
透過 SSE 協議主動推播訊息至前端，提醒線上玩家平台目前進行中的活動訊息或公告。支援廣播推送與單點推送，實現實時、低延遲的訊息傳遞。

## 規格說明

### 系統架構
```
後端服務 / 管理後台 / 第三方服務
         ↓ (REST API + API KEY)
         
Notification 微服務
  ↑ (內部: Redis + KDS)
  
前端 (客戶端 - SSE 長連接接收)
```

### 核心功能
- 後端服務、管理後台、第三方服務透過 REST API + API KEY 驗證呼叫
- 支援廣播推送（所有線上玩家）與個別推送（特定玩家清單）
- 同步返回推播狀態與統計資訊
- 訊息儲存與管理
- 將訊息歷史紀錄持久化儲存至 MySQL
- 支援不同玩家的歷史紀錄分離
- 自動清理過期訊息
- 離線玩家訊息暫存（支援 7 天離線儲存）
- 連接與佇列管理 
- Redis 連接池管理線上玩家狀態
- Redis Streams 暫時訊息緩衝
- KDS 事件流追蹤審計日誌

### 依賴系統
- 會員系統: 驗證玩家身份，取得玩家 ID、等級資訊、VIP 狀態
- 活動系統: 後端呼叫時可傳遞活動 ID 等元資料
- 權限系統: 驗證後端 API Key 權限，授予特定功能存取權限
- 其他後端服務: 訂單系統、行銷系統等可透過 API Key 呼叫推播 API

## API 設計規範

### 設計原則
- 後端推播 API (REST): 後端服務、管理後台、第三方服務使用 API Key 呼叫
- 訊息流向: 後端 → Notification 服務 → 前端（單向推播）
- 實時性: SSE 支援實時推播，延遲 [ 500ms (P99)
- 無狀態設計: Notification 服務可水平擴展

## API 端點總覽

後端服務呼叫 (REST API + API KEY):

| HTTP 方法 | 端點                                         | 功能     | 認證    | 說明                 |
|----------|----------------------------------------------|----------|---------|----------------------|
| POST     | `/api/v1/admin/notifications/broadcast`      | 廣播推送 | API Key | 發送給所有線上玩家   |
| POST     | `/api/v1/admin/notifications/send`           | 個別推送 | API Key | 發送給特定玩家清單   |
| GET      | `/api/v1/admin/notifications/stats`          | 統計資訊 | API Key | 推播統計與系統狀態   |

前端呼叫 (SSE + JWT):

| HTTP 方法 | 端點                                   | 功能         | 認證 | 說明                             |
|----------|----------------------------------------|--------------|------|----------------------------------|
| GET      | `/api/v1/notifications/stream`        | SSE 推播連接 | JWT  | 接收實時訊息（由前端實作）       |
| GET      | `/api/v1/notifications/history`       | 查詢歷史     | JWT  | 查詢歷史訊息（由前端實作）       |
| POST     | `/api/v1/notifications/{id}/mark-read`| 標記已讀     | JWT  | 標記訊息狀態（由前端實作）       |
| DELETE   | `/api/v1/notifications/{id}`          | 刪除訊息     | JWT  | 玩家刪除訊息（由前端實作）       |

## 訊息推播 API（後端實作）

### 廣播推送
端點:
#### POST `/api/v1/admin/notifications/broadcast`


認證:
- 使用 API Key
- Header: `Authorization: ApiKey <API_KEY>`

請求內容:
```
{
  "title": "系統維護通知",
  "message": "系統即將進行定期維護，造成的不便敬請見諒",
  "type": "system",
  "priority": "high",
  "icon_url": "https://...",
  "action_url": "https://...",
  "visibility": "visible",
  "expiry_at": "2026-02-01T12:00:00Z"
}
```

成功回應 (HTTP 200):
```
{
  "success": true,
  "message": "推送成功",
  "data": {
    "broadcast_id": "bcast_123abc",
    "total_players": 1250,
    "queued_count": 1250,
    "sent_at": "2026-01-30T15:30:00Z",
    "status": "queued"
  }
}
```

權限驗證失敗 (HTTP 403):
```
{
  "error": "Forbidden",
  "error_code": "INVALID_API_KEY",
  "message": "API Key 無效或權限不足"
}
```

## 資料模型
推播訊息物件:
```
{
  "notification_id": "string (UUID v4)",
  "player_id": "string (選擇性 - NULL 表示廣播)",
  "title": "string (最多 100 字元)",
  "message": "string (最多 500 字元)",
  "type": "enum (activity|promotion|system|announcement)",
  "priority": "enum (low|medium|high|critical)",
  "icon_url": "string (選擇性, URL)",
  "action_url": "string (選擇性, URL)",
  "visibility": "enum (visible|hidden)",
  "created_at": "timestamp (ISO 8601)",
  "expires_at": "timestamp (ISO 8601)",
  "metadata": {
    "event_id": "string (選擇性)",
    "campaign_id": "string (選擇性)"
  }
}
```

## 驗收標準
### 功能驗收

- 後端能成功廣播訊息給所有線上玩家

- 後端能成功發送訊息給特定玩家清單

- 可查詢推播統計資訊（日期、類型、優先級）
- 支援離線玩家訊息暫存（7 天保留）
- API Key 驗證正常運作
- 訊息格式驗證（字元長度限制、必填欄位）
- 訊息過期時間管理與清理機制

### 性能驗收
- 廣播推送吞吐量: > 10,000 QPS
- 訊息入隊延遲: 100ms (P99)
- 支援 1,000+ 個目標玩家的個別推送
- 可管理 10,000+ 個並發 SSE 連接
- 訊息遞送率: 99%

### 安全性驗收
- API Key 驗證有效實施
- 實施請求簽名驗證（選擇性）
- 所有推播事件記錄至 KDS（審計日誌）
- 敏感操作（API Key 輪換）紀錄完整
- 實施速率限制（防止濫用）

### 文件驗收
- API 文件完整 (Swagger/OpenAPI)
- 後端開發者指南與部署說明
- 推播 API 使用範例 (Go, Python)
