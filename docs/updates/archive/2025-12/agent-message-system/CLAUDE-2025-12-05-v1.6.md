## 功能概述
實現代理訊息活動的立即發送功能，當創建或更新活動時，如果符合立即發送條件（`status=scheduled` 且 `scheduled_at=nil`），系統將異步執行發送流程，確保API響應速度不受影響。

## 核心邏輯

### 立即發送判斷條件
```go
// 立即發送檢測邏輯
func (u *AgentUseCase) isImmediateSend(
    status consts.AgentCampaignStatus,
    scheduledAt *time.Time,
) bool {
    return status == consts.AgentCampaignStatusScheduled && scheduledAt == nil
}
```

### 狀態設計
- **草稿狀態**: `status=draft` - 暫存活動，不觸發發送
- **立即發送**: `status=scheduled` + `scheduled_at=nil` - 創建後立即異步發送
- **預約發送**: `status=scheduled` + `scheduled_at=設定時間` - 按時間排程發送

if u.isImmediateSend(consts.AgentCampaignStatus(req.Status), req.ScheduledAt) {

```go
func (u *AgentUseCase) processCampaignImmediate(
    ctx context.Context,
    campaign *entity.AgentCampaign,
) error {
    // 1. 更新狀態為發送中：sending
    if err := u.UpdateCampaignStatus(ctx, campaign.ID, consts.AgentCampaignStatusSending); err != nil {
        return err
    }

    // 2. 委託UseCase執行完整發送流程
    targetCount, sentCount, err := u.SendMessageToCampaignTargets(ctx, campaign)
    if err != nil {
        // 標記活動失敗
        u.UpdateCampaignStatus(ctx, campaign.ID, consts.AgentCampaignStatusFailed)
        return err
    }

    // 3. 更新統計與完成狀態
    return u.CompleteCampaign(ctx, campaign.ID, targetCount, sentCount)
}
```

### 4. Entity驗證邏輯

```go
func (ac *AgentCampaign) ValidateStatusAndSchedule() error {
    switch ac.Status {
    case consts.AgentCampaignStatusDraft:
        // 草稿狀態：scheduled_at 可帶可不帶
        return nil
    case consts.AgentCampaignStatusScheduled:
        if ac.ScheduledAt == nil {
            // 立即發送：status=scheduled，scheduled_at 不能帶
            return nil
        } else {
            // 預約發送：status=scheduled，scheduled_at 必須帶
            return nil
        }
    default:
        return fmt.Errorf("invalid status: %s. Must be 'draft' or 'scheduled'", ac.Status)
    }
}
```

## 性能優化

### 異步處理優勢
1. **API響應速度**: 創建/更新API立即返回，不等待發送完成
2. **系統穩定性**: 發送過程中的錯誤不會影響API響應
3. **並發處理**: 多個立即發送活動可並行處理
4. **資源隔離**: 使用獨立context避免請求超時影響

### 錯誤處理機制
1. **異步錯誤記錄**: 發送失敗記錄到日誌，不影響API響應
2. **狀態追蹤**: 通過OpenTelemetry追蹤異步處理過程
3. **優雅降級**: 發送失敗自動標記活動為failed狀態

1. **Handler層**: 接收API請求，驗證參數

3. **Entity層**: 驗證狀態與排程時間組合
4. **Repository層**: 數據持久化操作
5. **Service層**: 異步發送處理

### 與排程系統兼容
- 立即發送不影響現有的排程發送功能
- 排程系統繼續處理`status=scheduled`且有`scheduled_at`的活動
- 立即發送活動處理完成後狀態變為`sent`，不會被排程系統重複處理
