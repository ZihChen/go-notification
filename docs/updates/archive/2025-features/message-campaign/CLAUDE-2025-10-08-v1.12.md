# 商戶自動設定Active開關功能 v1.12

## 完成狀態：✅ 已完成 (2025-10-08)

## 功能概述
優化會員訊息自動派發設定，新增Active開關控制功能，提供更靈活的訊息推送管理。

## 🔧 技術實作詳情

### 1. DTO層更新
- **CreateOrUpdateMerchantAutoSettings**: Settings中的AutoSettingItem新增Active (bool)字段
- **GetMerchantAutoSettings Response**: AutoSettingSummary新增Active參數回傳
- **驗證規則**: Active字段為必填，使用`binding:"required"`進行驗證

### 2. 資料庫實體更新
- **MerchantAutoSetting實體**: 新增Active字段(bool類型)
- **資料庫遷移**: 自動處理新字段的DDL變更
- **向後兼容**: 現有資料預設Active為true

### 3. 業務邏輯增強
- **SendAutoNotification邏輯**: 驗證Active狀態，僅發送已啟用的設定
- **錯誤處理**: Active=false時回傳適當的錯誤訊息
- **狀態控制**: 商戶可彈性啟用/停用特定訊息類型的自動推送

### 4. API行為變更
- **設定查詢**: GET API回傳包含Active狀態的完整設定資訊
- **設定更新**: PUT API支援Active狀態的更新操作
- **推送驗證**: POST自動推送API檢查Active狀態才執行發送

### 5. 測試覆蓋
- **UseCase測試**: 涵蓋Active開關的各種業務場景
- **Handler測試**: 驗證API層的Active字段處理
- **邊界測試**: Active=false時的錯誤處理驗證

## 📋 實作變更摘要

### 檔案變更清單
1. `internal/application/dto/request.go` - AutoSettingItem新增Active字段
2. `internal/domain/entity/merchant_auto_setting.go` - 實體新增Active字段
3. `internal/application/usecase/message_campaign/send_auto_notification.go` - 業務邏輯驗證
4. 相關測試檔案 - 測試覆蓋更新

### API影響分析
- **向後兼容**: 現有API呼叫不受影響
- **新功能**: 提供Active字段的讀寫能力
- **錯誤處理**: 新增Active=false的錯誤回應

## 🎯 業務價值
- **精細控制**: 商戶可針對不同訊息類型進行開關控制
- **運營靈活性**: 支援動態啟用/停用自動推送功能
- **維護便利**: 無需刪除設定即可暫時停用功能
- **用戶體驗**: 減少不必要的訊息推送，提升使用者滿意度
